# Telegram AI Gateway — документация

## Обзор

Универсальный Telegram-бот, позволяющий каждому пользователю подключить собственные
OpenAI-совместимые API, зарегистрировать модели и общаться с ними прямо в Telegram.
Данные каждого пользователя полностью изолированы.

---

## Быстрый старт

```bash
cp .env.example .env
# заполните TELEGRAM_BOT_TOKEN и при желании измените пароли БД
docker compose up --build -d
```

---

## Команды

| Команда | Описание |
|---|---|
| `/add_api` | Добавить API-подключение (ключ + base URL) |
| `/api` | Список добавленных API |
| `/delete_api` | Удалить API (выбор из кнопок) |
| `/add_model` | Зарегистрировать модель |
| `/models` | Список моделей (с пометкой активной) |
| `/select_model` | Выбрать активную модель |
| `/delete_model` | Удалить модель |
| `/add_context` | Задать системный промпт / инструкции |
| `/context` | Показать текущий контекст |
| `/delete_context` | Очистить контекст |
| `/settings` | Сводка настроек + быстрые кнопки |
| `/help` | Справка |
| `/clear` | Очистить историю диалога с активной моделью |

## Типы моделей

### `chat`
Текстовый диалог с потоковой передачей (streaming). Поддерживает отправку
изображений — если модель принимает vision-запросы, картинка кодируется в base64
и вставляется в сообщение.

### `image`
Генерация изображений через `client.images.generate`. Бот скачивает результат
(URL или base64) и отправляет фото.

### `svg`
Модель просят вернуть чистый SVG-код. Бот отправляет `.svg`-файл и PNG-превью
(через `cairosvg`).

### `styled`
Генерация с референсным изображением. При регистрации модели пользователь
отправляет стилевое фото; оно хранится как `file_id` Telegram и передаётся
в каждый запрос.

## Архитектура

```
telegram-ai-gateway/
├── bot/
│   ├── main.py          # точка входа, polling, логирование
│   ├── config.py        # переменные окружения
│   ├── database.py      # SQLAlchemy async модели + CRUD
│   ├── handlers/        # aiogram-роутеры по доменам
│   └── services/        # ai_service (OpenAI SDK), image_service (Pillow/cairosvg)
├── docs/                # документация
├── logs/                # ротируемые логи (volume)
├── pgdata/              # данные PostgreSQL (volume)
├── Dockerfile
├── docker-compose.yml
└── .env.example
```

## База данных

| Таблица | Назначение |
|---|---|
| `user_apis` | API-подключения пользователя (имя, ключ, URL) |
| `user_models` | Зарегистрированные модели (тип, model_id, ссылка на API) |
| `user_contexts` | Системный промпт пользователя |
| `chat_history` | История сообщений по пользователю и модели (для контекста диалога) |

Таблицы создаются автоматически при старте (`init_db`).

---

## Логи

Файлы хранятся в `./logs/bot.log` (ротация: 10 МБ × 5 файлов).
Уровень задаётся переменной `LOG_LEVEL` (по умолчанию `DEBUG`).

Каждое AI-обращение логируется с `user_id`, именем модели и типом.
Ошибки — с полным traceback через `log.exception`.

---

## Переменные окружения

| Переменная | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather |
| `DATABASE_URL` | asyncpg URL для SQLAlchemy |
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `POSTGRES_DB` | Имя базы данных |
| `LOG_LEVEL` | Уровень логирования (`DEBUG`/`INFO`/`WARNING`) |

---

## Безопасность

- API-ключи хранятся в БД в открытом виде — разверните сервис только на доверенном сервере.
- Данные каждого пользователя изолированы по `user_id`; нет общего хранилища.
- Контейнер бота не открывает портов наружу.
