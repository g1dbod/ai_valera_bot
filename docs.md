# ai_valera_bot — документация

Универсальный Telegram-бот-шлюз к AI-моделям: пользователь сам добавляет
OpenAI-совместимые API (ключ + URL), сам регистрирует имена моделей, выбирает
активную модель и общается с ней в чате. Бот поддерживает текстовые чаты
(со стримингом), генерацию изображений через `/images`, модели со
«стилями» (референсное изображение), а также SVG-генерацию.

---

## 1. Что это и что умеет

| Возможность | Где реализовано |
|---|---|
| Мультипользовательский режим: у каждого свой набор API, моделей, контекста и истории | `database.py`, таблица `user_configs` |
| Добавление/удаление произвольных OpenAI-совместимых провайдеров | `bot.py:223`, `bot.py:259` |
| Добавление/удаление/выбор моделей, привязанных к API | `bot.py:305`, `bot.py:336`, `bot.py:389` |
| Системный промпт (контекст) на пользователя | `bot.py:451`–`bot.py:479` |
| История диалога в БД (последние 20 сообщений) | `bot.py:700` |
| Стриминг ответа с троттлингом редактирования сообщения | `bot.py:583` |
| Автоопределение типа модели: текстовый чат / image API / чат с картинками | `bot.py:689`–`bot.py:768` |
| Генерация картинок (`images.generate`), в т.ч. через роутеры-агрегаторы | `bot.py:612` |
| Модели, требующие образец стиля (`input_references`), включая SVG-вектор | `bot.py:617`–`bot.py:650` |
| Автофолбэк «чат не умеет — идём в /images» | `bot.py:722`–`bot.py:745` |
| Кэш клиентов `AsyncOpenAI` (переиспользование TCP/TLS) | `bot.py:43`, `bot.py:59` |
| Конвертация Markdown-подобного ответа в безопасный Telegram HTML | `bot.py:72` |
| Индикатор «печатает…», разбиение длинных ответов на части | `bot.py:495`, `bot.py:124` |

Чего бот **не** делает: не транскрибирует голосовые, не передаёт фото в
текстовые модели как изображение (фото используется только как референс
стиля для image API), не имеет админки, квот, тарифов и white-list.

### 2.2. `database.py` (49 строк)

- `DATABASE_URL` собирается из `POSTGRES_USER`, `POSTGRES_PASSWORD`,
  `POSTGRES_HOST` (по умолчанию `db`), `POSTGRES_DB` (`database.py:7`–`12`),
  драйвер — `postgresql+asyncpg`.
- `engine = create_async_engine(DATABASE_URL)` создаётся **на импорте**
  (`database.py:26`), поэтому некорректный DSN падает ещё до `main()`.
- `init_db()` — `Base.metadata.create_all` при старте (`database.py:29`).
  Миграций нет: схема только «досоздаётся», изменение колонок нужно делать вручную.
- `get_config(user_id)` — SELECT по PK, при отсутствии создаёт строку с
  `apis={}`, `models={}`, `history=[]` и коммитит (`database.py:34`).
- `save_config(config)` — `session.merge()` + commit (`database.py:46`).
  Объект передаётся «detached», поэтому merge — единственный корректный путь.

## 5. Быстрый старт

### 5.1. Docker Compose (основной способ)

```bash
# 1. Создать .env с BOT_TOKEN, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB
# 2. Собрать и запустить
docker compose up -d --build

# 3. Логи
docker compose logs -f bot

# 4. Остановить / удалить вместе с данными
docker compose down
docker compose down -v
```

Что происходит: поднимается `postgres:15` с томом `postgres_data`
(`docker-compose.yml:11`), затем контейнер бота собирается из `Dockerfile`,
при старте выполняет `init_db()` (создаёт таблицу, если её нет) и уходит в
long polling.

Полезные операции:

```bash
docker compose exec db psql -U bot_user -d ai_bot_db -c '\dt'
docker compose exec db psql -U bot_user -d ai_bot_db -c 'select user_id, selected_api, selected_model from user_configs;'
docker compose exec db pg_dump -U bot_user ai_bot_db > backup.sql   # бэкап
```

### 5.2. Локальный запуск

```bash
python -m venv .venv && .venv\Scripts\activate      # Windows
pip install -r requirements.txt
# Postgres должен быть доступен; POSTGRES_HOST=localhost
set BOT_TOKEN=...            # PowerShell: $env:BOT_TOKEN="..."
python bot.py
```

Для локального запуска нужен доступный Postgres: бот не умеет SQLite, драйвер
жёстко `asyncpg`, а host по умолчанию — `db` (имя compose-сервиса).

### 5.3. Переменные, которые не подхватятся сами

`python bot.py` не читает `.env` (нет `python-dotenv`). Переменные надо
экспортировать в окружение вручную — иначе `Bot(token=None)` упадёт.

## 6. Модель данных

Одна таблица, одна строка на пользователя Telegram.

```sql
CREATE TABLE user_configs (
    user_id        INTEGER PRIMARY KEY,
    apis           JSON,
    models         JSON,
    selected_api   VARCHAR,
    selected_model VARCHAR,
    context        TEXT,
    history        JSON
);
```

| Колонка | Тип | Смысл | Пример |
|---|---|---|---|
| `user_id` | Integer PK | Telegram ID пользователя | `123456789` |
| `apis` | JSON | словарь добавленных провайдеров | `{"openrouter": {"key": "sk-...", "url": "https://openrouter.ai/api/v1"}}` |
| `models` | JSON | словарь «API → список моделей» | `{"openrouter": ["gpt-4o-mini", "recraft-v3-styles"]}` |
| `selected_api` | String | имя активного API | `openrouter` |
| `selected_model` | String | имя активной модели | `gpt-4o-mini` |
| `context` | Text | системный промпт | `"Ты — ассистент по Python."` |
| `history` | JSON | список `{"role","content"}` | `[{"role": "user", "content": "привет"}]` |

Схема «богатая JSON-колонками»: гибко (список моделей у каждого свой), но
нельзя индексировать и фильтровать по моделям на стороне БД, а при параллельных
запросах одного пользователя возможна потеря обновлений (read-modify-write
без блокировки строки).

Инварианты, которые держит код:

- удаление API каскадно удаляет его модели (`bot.py:288`–`291`);
- если удалён/изменён активный API или модель, выбор сбрасывается
  (`bot.py:293`–`296`, `bot.py:375`–`378`);
- модель нельзя добавить к несуществующему API (`bot.py:320`);
- история обрезается до последних 20 элементов (`bot.py:704`);
- `/clear` чистит историю и образец стиля (`bot.py:482`), но не контекст.

Особенности ввода:

- `URL` должен быть базой OpenAI API, обычно с `/v1` на конце
  (`https://api.provider.com/v1`): SDK сам добавляет `/chat/completions`
  и `/images/generations`.
- В `/add_api` ключ и URL разбиваются по первым двум двоеточиям, поэтому
  `https://...` внутри URL не ломает разбор (`bot.py:227`).
- Свободный текст с символом `|` **игнорируется** — костыль от старого формата
  callback_data (`bot.py:783`). То есть фразу «a|b» бот молча пропустит.
- Голосовые и видео не распознаются: у них нет `text`/`caption`, подставляется
  заглушка `Generate an image` (`bot.py:694`).

## 8. Архитектура и поток обработки запроса

### 8.1. Маршрутизация апдейтов

```
Telegram update
   │
   ├─ Command("...")            → хендлер команды (настройки, контекст, история)
   ├─ BotStates.*               → пошаговый ввод (FSM на MemoryStorage)
   ├─ callback_query "del_api|" → удаление API
   ├─ callback_query "del_m|"   → удаление модели
   ├─ callback_query "set_m|"   → выбор модели
   ├─ F.text                    → handle_ai_request()   (если не "/" и без "|")
   └─ F.photo|document|voice|video → handle_ai_request()
```

Порядок регистрации важен: FSM-хендлеры (`@dp.message(BotStates.xxx)`)
объявлены раньше общих `F.text`, поэтому пока пользователь в состоянии ввода,
его текст не уходит в модель. Текстовые сообщения с `/` в начале обрабатываются
только командами (иначе бот ответил бы на неизвестную команду как на промпт —
сейчас такие сообщения просто игнорируются).

### 8.2. `handle_ai_request` — пошагово

1. Загрузить конфиг: `get_config(user_id)`.
2. Проверить, что выбраны API и модель; иначе — подсказка про `/select_model`.
3. Найти `apis[selected_api]`; если запись исчезла — попросить выбрать заново.
4. Взять `AsyncOpenAI` из кэша по `(key, url)`.
5. Отправить сообщение `🤔 Думаю над ответом...` и запустить фоновую задачу,
   которая каждые 4 с шлёт `typing`.
6. Собрать `messages`:

   ```python
   [{"role": "system", "content": config.context or ""}]
   + config.history
   + [{"role": "user", "content": message.text or message.caption or "Generate an image"}]
   ```

7. Выбрать путь по закэшированному типу модели:

| Условие | Путь |
|---|---|
| `known_type == "image_api"` | сразу `images.generate` (`bot.py:709`) |
| `known_type == "chat_text"` | стриминг чата (`bot.py:714`) |
| тип неизвестен | обычный `chat.completions.create` без стрима (`bot.py:723`) |

8. Fallback-и для «неизвестного» пути:

| Что пришло | Реакция |
|---|---|
| исключение содержит `/api/v1/images` или `image generation model` | тип := `image_api`, идём в `/images` |
| `200 OK`, но `choices` пуст | тип := `image_api`, идём в `/images` |
| в `message` есть нестандартное поле `images` с `data:image/...` | отправляем фото, тип := `chat_image` |
| есть `content` | текстовый ответ, тип := `chat_text` |
| нет ни текста, ни картинки | последняя попытка через `/images` |

9. Запомнить пару «вопрос-ответ» в историю и сохранить конфиг.
10. В `finally` отменить задачу `typing`; любое исключение → сообщение
    `❌ Ошибка API:` с экранированным текстом ошибки в `<pre>`.

Тип модели кэшируется по ключу `(user_id, api, model)` в памяти процесса
(`bot.py:46`), поэтому первый запрос к новой модели всегда нестримовый:
бот сначала «пробует» чат, а по характеру ответа или ошибке решает, что это
за модель.

### 8.3. Стриминг (`bot.py:583`)

```
stream=True → накапливаем full_text
каждые ≥1.2 с и при приросте ≥20 символов:
    preview = format_to_html(full_text) + " ▌"
    если len(preview) ≤ 4096 → safe_edit(...)
после конца потока:
    final_html = wrap_answer(full_text, model)
    первые 4000 симв. → safe_edit, остальные → отдельные сообщения
```

Троттлинг нужен, потому что Telegram ограничивает частоту правок сообщения
(примерно 1 правка в секунду на чат); `safe_edit` глушит ошибку
`message is not modified`, но остальные `TelegramBadRequest` только логирует.

### 8.4. Память диалога

`remember()` (`bot.py:700`) добавляет два элемента (`user`, `assistant`) в
`history` и обрезает список до последних 20 — это 10 полных реплик. Обрезка
не учитывает длину текста в токенах: длинные ответы могут переполнить контекст
модели и привести к ошибке API. Историю видят все последующие запросы
пользователя; `/clear` её обнуляет.

## 9. Генерация изображений и «стили»

`_run_image_api` (`bot.py:612`) используется в трёх случаях: тип модели уже
известен как `image_api`, провайдер ответил ошибкой про image-эндпоинт, или
чат вернул пустой ответ.

### 9.1. Референс стиля

1. Если в сообщении есть фото (`message.photo[-1]`, максимальное разрешение)
   или документ с `mime_type`, начинающимся на `image/`, файл скачивается
   и превращается в data-URI `data:<mime>;base64,...` (`bot.py:147`).
2. Data-URI кладётся в `_REFERENCE_CACHE[user_id]` — **один** список на
   пользователя, живёт в памяти процесса, в БД не сохраняется (`bot.py:54`).
3. Модель считается «со стилями», если её имя содержит `styles` или она уже
   была помечена в `_NEEDS_REFS` (`bot.py:623`).
4. Если референс нужен, а его нет — бот просит прислать картинку с
   подписью-промптом и подсказывает, что сбросить образец можно `/clear`.

### 9.2. Параметры запроса

| Случай | Аргументы `images.generate` |
|---|---|
| обычная модель | `model`, `prompt`, `n=1`, `size="1024x1024"` |
| модель со стилями | `model`, `prompt`, `n=1`, `extra_body={"aspect_ratio": "1:1", "input_references": [до 10 {"type": "image_url", ...}]}` |
| имя модели содержит `vector` | то же + `extra_body["output_format"] = "svg"` |

`extra_body` — способ передать нестандартные поля через официальный SDK,
поэтому бот работает и с провайдерами, расширяющими OpenAI-схему
(Recraft-подобные «styles»/«vector» модели).

### 9.3. Хитрости совместимости

- **Ошибка внутри тела ответа.** Роутер может вернуть `200 OK` с
  `data=None` и `error={...}`; SDK не бросит исключение. Код проверяет
  `img_response.error` вручную (`bot.py:655`).
- **Автоопределение требования `input_references`.** Если пришла ошибка,
  где упоминается `input_references`, а модель ещё не помечена как «со
  стилями», она добавляется в `_NEEDS_REFS` и запрос повторяется один раз
  с референсами (`bot.py:656`–`660`).
- **Извлечение картинки.** Сначала стандартные `data[0].url` /
  `data[0].b64_json`, затем regex-поиск URL картинки и `data:image/...;base64`
  в строковом представлении ответа (`bot.py:520`–`542`).
- **Отправка.** `bytes` → фото (`BufferedInputFile`, имя `gen.webp`);
  SVG → PNG-превью через `cairosvg` + сам SVG документом, а без `cairosvg`
  — только SVG документом; `url` → `answer_photo(photo=url)` (`bot.py:545`–`580`).
- **Пустой ответ.** Вместо картинки уходит первые 1000 символов дампа ответа,
  чтобы было видно, что вернул провайдер (`bot.py:670`).

### 9.4. Что попадает в историю

Вместо картинки в историю пишется строка `[Image Generated]`
(`bot.py:668`) или `[Image]` (`bot.py:764`) — то есть модель при следующем
запросе не «видит» сгенерированное изображение, только факт генерации.

## 10. Форматирование ответов

### 10.1. Markdown → Telegram HTML (`bot.py:72`)

Telegram понимает только свой HTML-диалект и падает на неэкранированных
символах (`<`, `>`, `&`), поэтому конвейер устроен так:

| Шаг | Действие |
|---|---|
| 1 | блоки ```` ```lang ... ``` ```` → `<pre><code>…</code></pre>`, спрятаны под плейсхолдер `\x00PHn\x00` |
| 2 | инлайн-код `` `code` `` → `<code>…</code>`, тоже под плейсхолдер |
| 3 | `html.escape` всего остального |
| 4 | заголовки `# … ######` → `<b>…</b>` |
| 5 | `**text**`, `__text__` → `<b>` |
| 6 | строки `- item`, `* item` → `• item` (до курсива, иначе конфликт с `*`) |
| 7 | `*text*`, `_text_` → `<i>` (с lookaround, чтобы не портить `snake_case`) |
| 8 | `[text](http…)` → `<a href="…">text</a>` |
| 9 | возврат плейсхолдеров с кодом |

Плейсхолдеры нужны, потому что код нельзя экранировать дважды и нельзя
применять к нему bold/italic. Содержимое код-блоков экранируется отдельно.

Не поддерживается: таблицы, цитаты `>`, зачёркивание `~~`, нумерованные
списки (остаются как есть), вложенные комбинации, а также заголовки внутри
кода (они уже спрятаны — корректно).

### 10.2. Подпись модели и разбиение

`wrap_answer()` (`bot.py:128`) добавляет в конец `— <i>model_name</i>`.
`split_text()` (`bot.py:124`) режет строку по 4000 символов **без учёта
HTML-тегов**: если тег попал на границу, часть сообщения может быть
невалидным HTML, и `answer()`/`edit_message_text` вернут `Bad Request:
can't parse entities`. Это редкий, но воспроизводимый дефект на очень
длинных ответах с форматированием.

## 11. Состояние в памяти и его жизненный цикл

Бот хранит в процессе несколько словарей (`bot.py:43`–`56`). Они не
персистентны и не разделяются между инстансами.

| Кэш | Ключ → значение | Зачем | Что происходит при рестарте |
|---|---|---|---|
| `_CLIENT_CACHE` | `(key, url)` → `AsyncOpenAI` | переиспользование TCP/TLS, экономия рукопожатий | пересоздаётся |
| `_MODEL_TYPE_CACHE` | `(user_id, api, model)` → `chat_text` / `chat_image` / `image_api` | не «пробовать» модель заново каждый раз | сбрасывается, первый запрос снова нестримовый |
| `_MODEL_SELECT_CACHE` | `user_id` → `[(api, model), …]` | индекс кнопок вместо длинных `callback_data` | кнопки перестают работать: «Список устарел» |
| `_API_DELETE_CACHE` | `user_id` → `[name, …]` | то же для удаления API | то же |
| `_MODEL_DELETE_CACHE` | `user_id` → `[(api, model), …]` | то же для удаления моделей | то же |
| `_REFERENCE_CACHE` | `user_id` → `[data-URI, …]` | образец стиля для image-моделей | образец нужно отправлять заново |
| `_NEEDS_REFS` | `{(api, model)}` | «эта модель требует `input_references`» | определяется заново по ошибке |
| FSM (`MemoryStorage`) | chat/user → состояние | пошаговый ввод `/add_api`, `/add_model`, `/add_context` | незавершённый ввод теряется |

Следствия:

- **Нельзя запускать несколько инстансов** бота с одним токеном: long polling
  Telegram допускает только один, а кэши и FSM не разделяются.
- После рестарта пользователю достаточно повторить `/select_model`,
  `/delete_api` и т. п. — это штатное поведение, а не ошибка.
- Память растёт с числом уникальных `(key, url)` и `(user_id, api, model)`.
  Для публичного бота это потенциальная утечка памяти; нужен LRU/TTL.

Для горизонтального масштабирования потребуется: `RedisStorage` для FSM,
перенос индексов кнопок в `callback_data` (например, с хэшем или с полным
именем через `quote`), а также lock/очередь на пользователя.

## 12. Требования к AI-провайдеру

Провайдер должен быть OpenAI-совместимым: SDK обращается к
`{base_url}/chat/completions` и `{base_url}/images/generations`.

Минимально достаточно:

- `POST /chat/completions` с `model`, `messages`, `stream`;
- `POST /images/generations` с `model`, `prompt` (для картинок);
- авторизация `Authorization: Bearer <ключ>`.

Дополнительно поддерживается:

| Расширение | Как обрабатывается |
|---|---|
| `image_url` в `message` (нестандартное поле `images`) | извлекается `data:image/...;base64` и отправляется как фото |
| ошибка в теле `200 OK` (`{"error": {...}}`) | распознаётся и показывается пользователю |
| требование `input_references` | ретрай с референсами |
| `aspect_ratio`, `output_format=svg` | передаются через `extra_body` |
| модель без `/chat/completions` | автофолбэк на `/images/generations` |

Практические замечания:

- `base_url` указывать с `/v1` на конце, иначе SDK сформирует неверный путь.
- Роутеры-агрегаторы (OpenRouter-подобные) часто отдают `200 OK` без
  `choices` для image-моделей — именно под это сделан фолбэк `bot.py:734`.
- Если провайдер требует `max_tokens` или запрещает `system`-сообщение,
  бот это не компенсирует: `messages` всегда начинаются с `system`
  (пустого, если контекст не задан) — некоторые строгие API на пустой
  `system` отвечают ошибкой 400.

## 13. Как расширять проект

### 13.1. Новая команда

```python
@dp.message(Command("mycmd"))
async def cmd_mycmd(message: types.Message):
    await message.answer("ok")

# и не забыть добавить в set_main_menu(), bot.py:166
```

Если команда должна вести диалог — добавьте состояние в `BotStates`
(`bot.py:32`) и хендлер `@dp.message(BotStates.my_state)` **до** общих
`F.text`-хендлеров (в текущем файле порядок уже соблюдён: все команды и
FSM-хендлеры объявлены выше `text_handler`).

### 13.2. Новая настройка пользователя

1. Добавить колонку в `UserConfig` (`database.py:16`).
2. Добавить её в `CREATE TABLE`-совместимое изменение (миграции нет —
   существующую БД придётся править вручную: `ALTER TABLE user_configs ADD COLUMN …`).
3. Задать дефолт в `get_config` при создании строки (`database.py:40`).
4. Использовать в `handle_ai_request`.

### 13.3. Новая логика работы с провайдером

Место — `handle_ai_request` (`bot.py:678`) и `_run_image_api` (`bot.py:612`).
Ориентир: любая нестандартная реакция провайдера должна приводить к
установке `_MODEL_TYPE_CACHE[cache_key]`, чтобы следующий запрос шёл сразу
правильным путём.

### 13.4. Переход на webhook / несколько реплик

- `dp.start_polling(bot)` → `aiohttp`-сервер + `dp.feed_update(...)`
  (aiogram 3), `bot.set_webhook(...)`.
- FSM → `RedisStorage.from_url(...)`.
- Индексы кнопок → данные в `callback_data` (лимит 64 байта) или в БД.

## 14. Эксплуатация

### 14.1. Логи

`logging.basicConfig(level=logging.INFO)` (`bot.py:25`). В stdout попадают:

| Сообщение | Когда |
|---|---|
| `Image API: model=…, refs=…, needs_refs=…` | перед каждым запросом картинки |
| `Chat API вернул 200 OK без choices для модели …` + дамп | при фолбэке на image API |
| `AI Error: …` + traceback (`exc_info=True`) | любое исключение в запросе к модели |
| `Menu error: …` | не удалось зарегистрировать команды в Telegram |
| `SVG preview unavailable: …` | нет `cairosvg`/`libcairo2` |
| `Edit failed: …` | неуспешная правка сообщения |

Логи не содержат ключей API (ключ живёт в объекте клиента), но содержат имена
моделей и полные дампы ответов в аварийных случаях — при передаче логов
третьим лицам учитывайте это.

### 14.2. Обновление и откат

```bash
git pull            # если появится репозиторий
docker compose up -d --build bot   # пересборка только бота
docker compose logs --tail=100 bot
```

Данные лежат в именованном томе `postgres_data`, поэтому пересборка бота и
пересоздание контейнера БД без `down -v` данные не удаляет.

### 14.3. Отказоустойчивость

- `restart: always` у обоих сервисов (`docker-compose.yml:6`, `:17`) —
  контейнер поднимется после падения и после перезагрузки хоста.
- `depends_on: db` **без** `condition: service_healthy` и без `healthcheck`:
  бот может стартовать раньше готовности Postgres. `init_db()` в этом случае
  упадёт, контейнер перезапустится по `restart: always`, и на следующей
  попытке всё заработает. Правильнее добавить в `db`:

  ```yaml
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -U $$POSTGRES_USER -d $$POSTGRES_DB"]
    interval: 5s
    retries: 10
  ```

  и в `bot`: `depends_on: db: {condition: service_healthy}`.
- Порт Postgres наружу не публикуется — БД доступна только внутри
  compose-сети. Для отладки используйте `docker compose exec db psql`.
- Graceful shutdown: aiogram по сигналу останавливает polling, но
  `engine.dispose()` не вызывается — при штатной остановке это не проблема,
  при частых перезапусках стоит добавить в `main()` блок `finally`.

### 14.4. Бэкапы

```bash
docker compose exec -T db pg_dump -U "$POSTGRES_USER" -Fc "$POSTGRES_DB" > dump.dump
docker compose exec -T db pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean < dump.dump
```

В дампе — ключи API пользователей в открытом виде (JSON-колонка `apis`),
поэтому хранить его нужно как секрет.

## 15. Ограничения и известные проблемы

### 15.1. Функциональные ограничения

| Ограничение | Причина | Последствие |
|---|---|---|
| Нет потоковой передачи изображений/прогресса генерации | `images.generate` синхронный | долгая «тишина» с индикатором `typing` |
| Фото не отправляются в чат-модели | в `messages` попадает только текст/подпись | vision-модели не видят картинку |
| Голос/видео не транскрибируются | нет `whisper`-шага | текст = `Generate an image` |
| Нет подсчёта токенов и обрезки по контексту | история режется по числу сообщений | ошибка 400 у моделей с малым окном |
| Нет стриминга для «неизвестных» моделей | сначала пробный нестримовый запрос | первый ответ медленнее |
| Нет системного промпта по умолчанию для новых пользователей | `get_config` создаёт `context=None`, а `UserConfig.context` default применяется только к INSERT через ORM-дефолт | в модель уходит пустая `system`-строка |
| `/delete_context` ставит `""`, а не дефолт | `bot.py:477` | поведение «без промпта», а не «helpful assistant» |
| Нет пагинации в списках кнопок | все кнопки одним сообщением | при десятках моделей клавиатура огромная |

### 15.2. Технические дефекты, которые стоит знать

| Дефект | Где | Влияние |
|---|---|---|
| Текст, содержащий вертикальную черту, игнорируется | `bot.py:783` | сообщение вида «a&#124;b» не обрабатывается |
| `split_text` режет по символам, а не по тегам | `bot.py:124` | возможный `can't parse entities` на длинных ответах |
| Read-modify-write всей строки при каждом ответе (`merge`) | `bot.py:700`, `database.py:46` | параллельные команды и ответы одного пользователя могут затереть друг друга |
| Кэши без TTL и лимита | `bot.py:43`–`56` | рост памяти |
| `_MODEL_SELECT_CACHE` живёт до перезапуска | `bot.py:49` | кнопки «протухают» после рестарта (обрабатывается сообщением об устаревании) |
| Зависимости без пинов | `requirements.txt` | невоспроизводимые сборки, возможные breaking changes aiogram/openai |
| `Dockerfile` без `cairosvg` и `libcairo2` | `Dockerfile` | SVG без превью |
| Нет миграций | `database.py:29` | ручной `ALTER TABLE` при изменении схемы |
| `version: '3.8'` в compose | `docker-compose.yml:1` | предупреждение об устаревшем ключе в новых версиях Docker Compose |
| Нет валидации URL/ключа при `/add_api` | `bot.py:227` | ошибки видны только при первом запросе |

### 15.3. Что происходит при ошибках

- Ошибка API → сообщение `❌ Ошибка API:` с текстом исключения; черновик
  «Думаю…» заменяется на этот текст (если правка не удалась — отправляется
  новое сообщение).
- Ошибка картинки, но ответ получен → дамп первых 1000 символов.
- Ошибка Telegram при правке → только лог, пользователь остаётся с прежним
  текстом сообщения.

## 16. Безопасность и приватность

| Аспект | Текущее состояние | Рекомендация |
|---|---|---|
| Доступ к боту | любой пользователь Telegram может писать боту и заводить свои ключи; white-list нет | список `ALLOWED_USER_IDS` + фильтр на `dp.message`/`dp.callback_query` |
| Ключи API | хранятся в открытом JSON в Postgres | шифрование на уровне приложения (Fernet/KMS) или секрет-менеджер |
| `.env` | рабочие токен и пароль лежат в каталоге, `.gitignore` нет | исключить из VCS, ротировать секреты |
| SQL-инъекции | исключены: только ORM и параметризованные запросы | — |
| HTML-инъекции в сообщениях | текст модели экранируется `html.escape`, имена — тоже | — |
| Утечка ключа в логи | ключ не логируется | не добавлять `repr(client)` в логи |
| Ошибки API пользователю | отправляется текст исключения | при публичном боте стоит обрезать детали |
| Rate limiting | отсутствует | ограничение запросов на пользователя |
| Публичные URL картинок | `answer_photo(photo=url)` — URL загружает Telegram, а не сервер бота | SSRF на хосте бота нет |
| Приватность | промпты и ответы хранятся в БД (`history`, `context`) и уходят стороннему провайдеру | предупредить пользователей, добавить `/delete_me` для удаления строки |

Важно: бот **не является** прокси с вашим ключом — каждый пользователь вводит
свой ключ и тратит свою квоту. Но если вы развернули бота публично, вы
отвечаете за хранение чужих ключей в своей БД.

## 17. Диагностика

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Контейнер `bot` падает сразу | не задан `BOT_TOKEN` | проверить `.env`, `docker compose config` |
| `TokenValidationError` / `InvalidToken` | токен отозван или с опечаткой | перевыпустить токен у @BotFather |
| `no such table: user_configs` | `init_db()` не выполнился (БД была недоступна) | перезапустить бот, проверить логи Postgres |
| `Connect call failed` / `getaddrinfo failed` | неверный `POSTGRES_HOST` (локальный запуск с `db`) | `POSTGRES_HOST=localhost` |
| `❌ Сначала выберите модель` | не вызван `/select_model` | выбрать модель |
| «Список устарел, вызовите /delete_model заново» | рестарт бота сбросил кэш кнопок | повторить команду |
| Ответ приходит целиком, без «печати» | модель ещё не в `_MODEL_TYPE_CACHE` | это норма для первого запроса |
| `❌ Ошибка API: … 401` | неверный ключ или `base_url` | проверить `/add_api` (URL с `/v1`) |
| `❌ Ошибка API: … 404` | `base_url` без `/v1` либо модель не существует | исправить URL/имя модели |
| Image-модель отвечает текстом про генерацию | провайдер не поддерживает `/images` | проверить документацию провайдера |
| «Этой модели нужен образец стиля» | имя содержит `styles` или сработал `_NEEDS_REFS` | отправить картинку с подписью-промптом |
| `can't parse entities` на длинном ответе | `split_text` разрезал HTML-тег | уменьшить ответ или починить разбиение |
| В логах `409 Conflict` | запущено два инстанса с одним токеном | оставить один |
| Постоянный `typing` после ответа | задача не отменилась (исключение до `finally`) | проверить traceback в логах |
| Пустые ответы у строгой модели | пустая `system`-строка | задать контекст через `/add_context` |

Быстрая проверка окружения без Docker:

```powershell
$env:BOT_TOKEN="..."; $env:POSTGRES_HOST="localhost"
python -c "import asyncio; from database import init_db; asyncio.run(init_db()); print('db ok')"
```

```
/models
/delete_model → [openrouter | recraft-v3-styles]
/delete_api → [openrouter]               → удаляет и API, и его модели, и выбор
```

Ключевые правила:

1. Сначала `/add_api`, потом `/add_model`, и только потом `/select_model` —
   модель нельзя привязать к несуществующему API.
2. Имя API в `/add_model` должно **точно** совпадать с именем из `/add_api`
   (регистр и пробелы важны).
3. Для SVG-моделей признак — подстрока `vector` в имени модели;
   для моделей со стилями — подстрока `styles` (либо автоопределение по ошибке).
4. Образец стиля хранится в памяти: после рестарта бота его нужно отправить снова.

## 20. Глоссарий

| Термин | Значение в этом проекте |
|---|---|
| API-запись | `{name: {key, url}}` — провайдер, добавленный пользователем |
| Модель | строка, которую бот передаёт в поле `model` запроса |
| Контекст | системный промпт (`system`-сообщение) |
| История | последние 20 сообщений диалога, хранятся в JSON |
| Тип модели | `chat_text` / `chat_image` / `image_api`, определяется автоматически |
| Референс | картинка-образец стиля в виде `data:` URI |
| `input_references` | нестандартное поле image API для передачи референсов |
| Фолбэк | переход с `/chat/completions` на `/images/generations` |
| FSM | конечный автомат aiogram для пошагового ввода |
| `callback_data` | строка в инлайн-кнопке: здесь это префикс, вертикальная черта и индекс |
